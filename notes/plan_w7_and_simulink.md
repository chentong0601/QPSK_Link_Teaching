# W7 方案与 Simulink 定位（设计决策）

> 制定日期: 2026-09-10 | 性质: 内部设计决策文档（非外部资料）
> 背景: 参考库积累到 3 份官方示例后，重新审视"通信接收机"该如何补完，
>       并确定 Simulink 在项目中的定位。
> 结论: **W7 = 定时精调 + 判决导向 PLL；Simulink = 只做展示层（不重写算法）。**

---

## 一、决策摘要

| 议题 | 决策 | 一句话理由 |
|---|---|---|
| W7 补什么 | **定时精调 + 判决导向 PLL** | 补齐接收机两个标准部件，才算"完整接收机" |
| 定时方案 | **TED + 一次插值**（不做完整 Gardner） | 前导已完成粗捕获，不需要盲搜 |
| 相位方案 | **前导定初值 + 判决导向 PLL** | 前导消解 4 重相位模糊，避免跳周 |
| Simulink | **只做展示层（实时监视器 + 离线可跑模型）** | Simulink 的不可替代性是"仪器化呈现"，不是"算法实现" |
| 不做 | **全盘 Simulink 重写** | 算法零新增、双实现分叉、无法自动化回归 |

## 二、W7：接收机补完方案

### 2.1 现状与缺口

W6 链路：
```
帧检测(归一化相关) → 匹配滤波 → 固定抽样 → 频偏估计/补偿
                   → 常数相位校正 → 判决 → 解扰 → 帧头解析
```

**两个缺口**：

| 缺口 | 现状 | 后果 |
|---|---|---|
| 定时 | 固定抽样（相关峰整数采样点），残余误差 ≤ 0.5 采样 = **T/8**（L=4） | 引入 ISI；低 SNR / 长帧 / 有漂移时劣化 |
| 相位 | 只用前导做**一次性**常数校正 | 无法跟踪帧内相位漂移（温漂、LO 漂移、慢衰落） |

### 2.2 四个关键判断（决定了工作量与可行性）

#### 判断一：定时**不做**完整 Gardner 环路

Gardner（内插滤波 + 误差检测 + 环路滤波 + 环路控制）是为**盲捕获**设计的
——接收端完全不知符号边界，需搜索。

本项目：**前导归一化相关已把帧起点定到 ±1 采样内**，粗捕获已完成，
只需**精调**。故采用：

```
定时误差检测 (TED, 早迟门 / Oerder-Meyr)
  → 一次插值 (抛物线 / 三次) 把抽样点移到真峰
```

**不需要环路滤波器，不需要插值控制器。** 复杂度约完整 Gardner 的 1/3，
本场景下性能等价。

> 报告价值：把"为什么不需要盲捕获"写成设计判断 —— 展示工程取舍能力。

#### 判断二：相位跟踪用**前导做初值**

判决导向 PLL 的已知陷阱：**QPSK 4 重相位模糊**。判决相对当前星座进行，
若相位整体旋转 90°，判决随之旋转 → PLL 锁死在错误相位（**跳周**）。

本项目已有**公共相位校正**（W3 关键修复）产出的 `ph0`，
正好作为 PLL 初始相位 → PLL 只跟踪前导之后的**小**残余漂移 → 跳周风险基本消除。

> 这一步是把 W3 的成果从"开环校正"升级为"闭环跟踪"，衔接自然。

#### 判断三：顺序固定为 **定时 → 相位**

判决导向的相位误差检测**依赖判决正确**；定时误差会导致判决出错。
故定时必须在前，否则相位环被错误判决污染。

#### 判断四：W7 价值**必须用对抗实验证明**（最重要）

**诚实的风险**：当前理想条件下（Eb/N0 ≥ 2 dB 已 100% 解帧），
W7 的指标改进可能很小（T/8 定时误差的 ISI 损失在亚 dB 级）。
若加进去指标不变，在报告里就是"为了做而做"。

**对策：人为注入 W6 无法应对的损伤，让 W6 崩、W7 稳。**

| 注入损伤 | W6 预期 | W7 预期 | 产出图表 |
|---|---|---|---|
| 抽样相位偏移（T/4、T/2） | BER 上升 | 插值补偿后基本不变 | BER–定时误差曲线 |
| 缓慢相位漂移（温漂模拟） | 帧内后段出错 | PLL 跟住，全帧正确 | 相位漂移容限曲线 |
| 长帧 / 多帧累积漂移 | 后段帧失败 | 每帧重新精调 | 连续解帧成功率 |

→ 这些曲线才是**能写进报告的量化证据**。

### 2.3 实施步骤

| 步 | 内容 | 验收 |
|---|---|---|
| W7a | 定时误差检测 + 插值精调，接入 `rx_frame` | 注入 T/4 定时偏移，BER 恢复至无偏移水平 |
| W7b | 判决导向 PLL，前导定初值 | 注入相位漂移，全帧正确；无跳周 |
| W7c | 对抗实验矩阵 + 曲线 | BER–定时误差 / 相位漂移容限曲线各一张 |
| W7d | 回归测试（W1~W6 不退化）+ 笔记 | 全部 PASS |

## 三、Simulink：定位为"展示层"

### 3.1 三种用法的定位

| 用法 | 成本 | 价值 | 决策 |
|---|---|---|---|
| **A 实时接收监视器** | 低 | 高 | ✅ **做** |
| **B 离线可跑演示模型** | 中（**因复用函数而降低**） | 中高 | ✅ **做** |
| C 全盘 Simulink 重写 | 极高 | 低 | ❌ **不做** |

### 3.2 ★ 关键技巧：用 MATLAB Function 块**调用**现有 `.m` 函数

这是把 B 从"高成本"降为"可接受"的核心手法，也彻底消除分叉风险：

```
Simulink 模型 = 外壳（数据流 + 可视化）
算法内核     = 同一份 .m 代码（rx_frame / freq_sync / ... 被调用，不重写）
```

**收益**：
- 算法只有**一个真源**（`.m`），不存在"改一处要改两处"
- 答辩若被问"哪个是对的"，答案是确定的：`.m` 是基准
- Simulink 侧只需连线与显示，工作量集中在块图而非算法

### 3.3 为什么**不做**全盘重写（C）

1. **算法零新增**：Simulink 里跑的还是同一套同步/解调逻辑，知识增量是零
2. **双实现分叉**：同一算法两处维护，一旦不一致，答辩时解释成本极高
3. **无法自动化回归**：硬件 Simulink 模型**只能 GUI 跑**
   （已验证：`-batch` 模式不注册 Support Package 路径）
   → 不能进回归测试。**核心算法不应放在无法自动测试的地方。**

### 3.4 A / B 的具体内容

**A. 实时接收监视器**（现场演示）
```
Pluto RX → 去 DC → [频谱分析仪] + [星座图] + [功率/RMS 表]
```
- 复用参考 #1 的 `spectrumAnalyzer` 用法（`FrequencyOffset` = 中心频率）
- 现场效果：频谱在动、星座在收敛 —— 比静态图有说服力

**B. 离线可跑演示模型**（答辩保底 + 报告架构图）
```
From File (results/w3_rxData.mat) → MATLAB Function (调用 rx_frame)
  → 显示解出文本 + 星座图 + 相关峰
```
- **不依赖硬件**：现场硬件出问题（天线掉/驱动异常/环境干扰）时的风险对冲
- 块图本身可作报告的**系统架构图**

**D. 双板频偏标定**（借力，可选）
- 直接跑官方模型 `plutoradiofreqcalib` / `plutoradiofreqcalib_rx`（参考 #3）
- 极低成本；是双板实验的前置步骤

## 四、"优势"该怎么表述

**不要**表述成"我们还做了个 Simulink 版" —— 那只是复述劳动量，不是优势。

**要**表述成**三层分工的方法论**：

| 层 | 载体 | 承担什么 | 为什么这样选 |
|---|---|---|---|
| 算法层 | `.m` 函数/脚本 | 算法研究、批量实验、**自动化回归** | 可脚本化、可复现、可回归测试 |
| 系统层 | Simulink 模型 | 实时仪器化、系统级演示、架构视图 | 实时可视化与应用生态是 Simulink 的强项 |
| 实验层 | 硬件 + 官方模型 | 真实空口实测、双板频偏标定 | 实测数据 + 借力官方验证过的工具 |

**实证支撑**：`.m` 链路每次改动都回跑 W1~W6 回归 ——
这件事 Simulink 做不到，正是把算法放在 `.m` 里的理由。
把这个理由讲清楚，本身就体现工程判断力。

> ⚠️ **注意一个容易说错的点**：
> 因为 B 复用同一份 `.m` 函数，所以它**不是**"双实现交叉验证"。
> 真正独立的交叉验证是 **参考 #3 的 FFT 找峰 vs 我们的相位差法**
> （原理完全独立）。不要把两者混淆，否则报告会被问倒。

## 五、执行顺序与优先级

| 序 | 任务 | 说明 |
|---|---|---|
| 1 | **W7a + W7b**（算法） | 核心交付，优先做 |
| 2 | **Simulink A 实时监视器** | 成本低、见效快，可穿插做 |
| 3 | **W7c 对抗实验 + 曲线** | 证明 W7 价值，报告关键图 |
| 4 | **Simulink B 离线模型** | 答辩保底 + 架构图 |
| 5 | 报告整合 | 把 W7 与 Simulink 定位写进报告 |
| 6 | 双板实验（待第二块板） | 先用官方模型标定频偏 |

**若时间紧张**：B 可降级 —— 保留块图作架构图，不追求可运行；
A + W7 是不可砍的核心。

## 六、风险与对策

| 风险 | 对策 |
|---|---|
| W7 改进不明显 | 用对抗实验放大差异（判断四） |
| Simulink 硬件模型 GUI 依赖 | 只用它做演示，不作为交付主链 |
| 时间不足 | 按 §5 优先级裁剪，保 W7 + A |
| 双板频偏超量程（参考 #2/#3） | 先做硬件粗校正，再跑 QPSK |
| 答辩硬件故障 | B（离线模型）+ `.m` 脚本双保底 |
