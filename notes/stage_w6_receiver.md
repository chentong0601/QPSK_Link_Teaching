# W6 — 通信接收机：连续接收状态机

> 本阶段目标：把"抓一帧解一帧"的实验脚本，升级成**能持续工作的通信接收机**。
> 这是课程"做一个通信接收机"要求的核心交付物。

---

## 1. 为什么要做这一步

前五个模块（W1–W5）解决的是：**怎么把一帧数据正确解出来**。
但真实接收机面对的是**连续不断的采样流**，它必须自己回答三个问题：

| 问题 | 前五个模块的做法 | 接收机的做法 |
|------|-----------------|-------------|
| 信号从哪开始？ | 已知起点（或整段里找最大峰） | 边收边找，找到就切 |
| 找到之后怎么办？ | 一次性处理完 | 切走这一帧，继续往下找 |
| 找不到怎么办？ | 报错退出 | 继续收，等下一帧 |

所以 W6 的新东西只有一个：**状态机 + 滑动缓冲**。

---

## 2. 核心技术点

### 2.1 归一化相关（本阶段最重要的改进）

**旧做法**（幅度相关）：

$$C[n] = \left|\sum_m r[n+m]\,p^*[m]\right|,\qquad \text{门限} = 5\sqrt{\overline{|r|^2}/L}$$

问题：门限依赖**整段数据的平均功率**。在连续接收中，缓冲里既有强帧区又有纯噪声区，
一个固定门限要么在噪声区频繁虚警，要么在弱帧区漏检。

**新做法**（归一化相关 = 相关系数）：

$$\rho[n] = \frac{\left|\sum_m r[n+m]\,p^*[m]\right|}{\sqrt{E_r[n]\cdot E_p}},
\qquad E_r[n]=\sum_m |r[n+m]|^2,\quad E_p=\sum_m|p[m]|^2$$

性质：
- $\rho \in [0,1]$，**与接收信号幅度完全无关** → 门限可以固定，跨块稳定。
- $\rho \to 1$ 表示"这段接收波形与已知前导形状几乎完全一致"。
- 无帧时 $\rho$ 只反映噪声与随机数据的偶然相关。

这本质上是**匹配滤波输出的归一化判决统计量**，和假设检验里的
**归一化似然比**是同一个思想。

### 2.2 门限标定（实测数据说话）

实测（Eb/N0 = 12 dB）：

| 类别 | ρ 范围 |
|------|--------|
| **真峰**（帧起点） | **0.90 ~ 0.91** |
| 噪声旁瓣 / 虚警 | 0.35 ~ 0.44 |
| 纯噪声底 | ~0.17 |

取 **门限 = 0.60**，两侧各留约 1.5 倍余量。
（早期用 0.35 时，噪声旁瓣被误判为帧 → 缓冲被错误消费 → 后续帧全崩，
表现为"帧号错乱 0 200 106 123 210"。）

### 2.3 帧起点的对齐关系（易错点）

`conv(rxWave, conj(flipud(p)))` 的相关峰出现在

$$k_{\text{peak}} = \text{帧起点} + N_p - 1$$

切掉前 $N_p-1$ 个采样后，索引 $\text{idx} = k_{\text{peak}}-(N_p-1) = \text{帧起点}$。

> **结论**：归一化相关序列 `corrMetric(idx)` 的索引 **本身就是帧起点**，不需要再换算。
> 直接减 $N_p-1$ 是常见错误（会整体前移 151 个采样）。

### 2.4 滑动缓冲的消费逻辑（第二个坑）

解出一帧后，必须把这一帧（连同过渡带）从缓冲里**丢掉**，否则会反复解同一帧。
但丢多了会**啃掉下一帧的前导**，导致后续帧全部失败。

正确做法：

```matlab
consumed = dg.frameStart + NsymTotal*L + L;   % 帧体长 + 1 符号过渡带
buffer = buffer(consumed+1:end);
```

关键：消费量用**帧体长** `NsymTotal*L`（不含 RRC 拖尾），因为拖尾属于帧间过渡，
本来就要丢；再加 1 个符号确保下一帧前导干净。

## 3. 代码结构

```
sync/frame_detect.m        归一化滑动相关 + 固定门限 → 返回帧起点
receiver/rx_frame.m        单帧处理链（检测→抽样→频偏→相位→判决→解扰）
receiver/rx_receiver.m     连续接收状态机（滑动缓冲 + 循环解帧）★W6新增
main_w6_receiver.m         20 帧 + 320 Hz 频偏 验证
main_w6_sweep.m            Eb/N0 灵敏度扫描 → plots/w6_sensitivity.png
```

`rx_receiver` 主循环骨架：

```
while 没解够目标帧数 and 没超时:
    newData = 读一块新采样            % 硬件: rx(); 仿真: 切一块
    buffer = [buffer; newData]        % 滑动缓冲
    while 还能从 buffer 里解出帧:
        尝试 rx_frame(buffer)
        成功  → 输出 payload, 消费到帧末尾
        不完整 → 退出内循环, 等下一块
        未检出 → 丢弃一段, 继续
```

## 5. 踩坑记录

| # | 现象 | 根因 | 修复 |
|---|------|------|------|
| 1 | 帧号错乱 0 200 106 123 210 | 相关峰索引被当成帧起点（差 $N_p-1$） | 明确 corrMetric 索引即帧起点 |
| 2 | 5 帧只解出 1 帧 | 缓冲消费越界，啃掉下一帧前导 | 消费量改用帧体长 + 1 符号 |
| 3 | 修正后 0 帧检出 | 门限 0.35 过低，但 Er 长度 off-by-one 报错 | 修 Er 切片为 `cumP2(Np+1:Np+Nc)` |
| 4 | 偶发解出乱码帧 | 噪声旁瓣 ρ=0.35~0.44 误判为帧 | 门限提到 0.60 |
| 5 | W2 扫描报"帧不完整" | 完整性判据过于严格（多算了一步） | 判据改为 `(NsymTotal-1)*L+1` |

## 7. 与"完整接收机"的差距（下一步）

W6 已实现**连续接收**，但仍有两项真实接收机的核心功能缺失：

| 缺失 | 现状 | 影响 |
|------|------|------|
| **符号定时同步**（Gardner） | 靠相关峰整数采样点定位 | 采样相位偏差 > T/4 时性能劣化 |
| **相位跟踪**（判决导向 PLL） | 只用前导做一次性公共相位校正 | 无法跟踪帧内相位漂移 / 慢衰落 |

（当前仿真下这两项不构成致命问题，因为频偏已由前导估清、相位近似常数；
但真实动态信道下必须补上。可作为 W7 内容。）
