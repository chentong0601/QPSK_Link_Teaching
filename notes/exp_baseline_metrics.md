## E1. 帧检测 ρ 随载波频偏的衰减（帧检测自身的频偏容限）

条件：Eb/N0 = 20 dB，20 次平均；前导时长 `Tp = 32/250k = 128 µs`

| 频偏 (Hz) | ρ(真起点) | 能否检出（门限 0.60） |
|---|---|---|
| 0 | 0.944 | ✅ |
| 200 | 0.943 | ✅ |
| 500 | 0.938 | ✅ |
| 1000 | 0.920 | ✅ |
| 2000 | 0.847 | ✅ |
| 3000 | 0.732 | ✅ |
| 3500 | 0.663 | ✅ |
| **4000** | **0.587** | ❌ |
| 4500 | 0.507 | ❌ |
| 5000 | 0.425 | ❌ |
| 6000 | 0.260 | ❌ |

**理论模型**：前导相关幅度按 `sinc(Δf·Tp)` 衰减。
需要 `0.944·sinc(Δf·Tp) > 0.60` ⇒ `sinc > 0.636` ⇒ `Δf·Tp ≈ 0.5`
⇒ **Δf ≈ 0.5/128µs = 3906 Hz**

**实测 ≈3.9 kHz，理论 3.91 kHz → 完全吻合。** ✅

> **推论（重要）**：帧检测的容限（3.9 kHz）**比频偏估计器的量程（±5208 Hz）更窄**。
> 因此"频偏容限"的真实瓶颈是**帧检测**，不是估计器。
> 双板实验前必须做硬件粗校正，否则连帧都找不到。

## E2. 误码在帧内的位置分布（根因定位）★

条件：Eb/N0 = 8 dB，真频偏 = 0，200 次平均，按帧内位置分段

| 符号区间 | A：用估计值补偿（=rx_frame 做法） | B：理想（已知真频偏） |
|---|---|---|
| 1–37 | 0.0000 | 0.0000 |
| 38–74 | 0.0008 | 0.0000 |
| 75–111 | 0.0107 | 0.0000 |
| 112–148 | 0.0597 | 0.0000 |
| 149–185 | 0.1469 | 0.0000 |
| 186–222 | 0.2347 | 0.0000 |
| 223–259 | 0.3170 | 0.0000 |
| 260–296 | **0.3857** | 0.0000 |
| **总 BER** | **0.1444** | **0.0000** |

**A 列的 BER 从帧首到帧尾单调恶化 0 → 0.386；B 列全帧为 0。**

⇒ **误码完全来自频偏估计器的误差**，它使补偿后的残余变成一个**跨帧的相位斜坡**，
越靠帧尾相位偏移越大，直至越过 QPSK 的 45° 判决边界。

**量化**：实测 `freqEst` 标准差 = 133.3 Hz（真值 0）
⇒ 帧内相位漂移 = `133.3 × 360 / 250k × 296` = **56.8°** > 45° ⇒ 帧尾必错。

## E3. BER vs Eb/N0：现有接收机 vs 理想同步

条件：真频偏 = 0，200 次平均

| Eb/N0 | A：现有方式 | B：理想同步 | freqEst 标准差 | 帧内相位漂移 |
|---|---|---|---|---|
| 4 dB | 0.2971 | 0.0087 | 211.2 Hz | 90.0° |
| 6 dB | 0.2149 | 0.0007 | 167.8 Hz | 71.5° |
| 8 dB | 0.1444 | 0.0000 | 133.3 Hz | 56.8° |
| 10 dB | 0.0869 | 0.0000 | 106.0 Hz | 45.2° |
| 12 dB | 0.0445 | 0.0000 | 84.2 Hz | 35.9° |
| 16 dB | 0.0040 | 0.0000 | 53.2 Hz | 22.7° |
| 20 dB | 0.0000 | 0.0000 | 33.6 Hz | 14.3° |
| 25 dB | 0.0000 | 0.0000 | 18.9 Hz | 8.1° |

**关键观察**：
- 现有接收机要 **≈20 dB** 才能无误码；理想同步 **8 dB** 即无误码 → **差距约 12 dB**
- BER 与"帧内相位漂移"高度相关，验证 E2 的因果判断
- `freqEst` 均值与 0 的偏差很小（-14 ~ +0.1 Hz），但**标准差很大**（19~211 Hz）
  → 说明估计器**无偏但精度不足**（复用了 8 符号相干平均，噪声抑制有限）

> **W7b 的量化目标**：使曲线 A 逼近曲线 B。即让相位跟踪吸收这个帧内斜坡。

## E4. 载荷长度对解帧成功率的影响（"20/20"是假象）★

条件：320 Hz 频偏，20 帧

| Eb/N0 | 载荷 10 字节 | 载荷 62 字节（满） |
|---|---|---|
| 12 dB | 20/20 | **11/20** |
| 16 dB | 20/20 | 16/20 |
| 20 dB | 20/20 | 20/20 |
| 25 dB | 20/20 | 20/20 |

**机理**：误码集中在帧尾（E2），而 10 字节消息只占载荷区**前 40 个符号**（符号 49–89，位于低误码区），
其余 208 个符号是**补零后被丢弃**的区域，错误被自动丢弃。
⇒ 短消息**系统性地隐藏了误码**。

> **修正**：`main_w6_receiver` / `main_w6_sweep` 的默认消息应改为**满载荷**，
> 否则指标虚高。这也是评审"20/20 不能充分证明"的更深一层原因。

## E6. Eb/N0 标定偏差（1.83 dB）

`main_w6_receiver` 等脚本用 `sigma = sqrt(1*Eg/(2*EbN0*bp))`，隐含假设符号能量 Es = 1。
实测：

| 量 | 值 |
|---|---|
| `Eg = sum(rrc.^2)` | 1.000000 |
| 归一化后波形 `mean|w|²` | 0.3358 |
| 符号能量 `Es = L·mean|w|²` | **1.3699** |
| 标称 Eb/N0 = 8 dB 时实测 Es/N0 | 12.83 dB（应 11.0 dB） |
| ⇒ 实际 Eb/N0 | **9.83 dB（比标称高 1.83 dB）** |

**根因**：`w*0.9/max(abs(w))` 把信号抬高了 1.171 倍，但噪声未同步缩放。
**修正**：`sigma = sqrt(Es/(2*EbN0*bp))`，其中 `Es = L*mean(abs(w).^2)` 在归一化**之后**计算。

> 影响面：W2 扫描、W6 灵敏度、本文档 E3/E5 的**所有 Eb/N0 标称值偏高约 1.83 dB**。
> 本文档已按此标注，但对比时需注意统一基准。

## E9. 去直流效果（用真实空口数据）

数据：`results/w3_rxData.mat`

| 指标 | 值 |
|---|---|
| DC 分量 | 1.32e-5 + j(-1.22e-5) |
| \|DC\| / RMS | **0.05 %** |
| 去 DC 前 | ρ_max = 0.9447，freqEst = −107.5 Hz，解出 "HELLO QPSK!" |
| 去 DC 后 | ρ_max = 0.9448，freqEst = −107.8 Hz，解出 "HELLO QPSK!" |

**结论：本系统 DC 偏置可忽略**（很可能因 AD9363 内置 DC 跟踪环路已生效）。
去直流**不改变**解调结果，故**不作为优先级项**。

> **澄清**：评审建议"提升 DC 去除优先级"。就**我们的实测数据**而言，收益为零。
> 该建议在通用 SDR 语境下成立，但不适用于本系统的实测情况。
> 仍可保留 3 行去 DC 代码 + "去前/去后频谱"对比图作为工程完整性的展示，但**不必投入更多**。
