## 1. 项目背景与课程要求

- **课程要求**：设计并实现一个**通信收发系统**（接收机为核心）。
- **附加要求**：需要现场演示；评价依据包括系统完整性、技术深度、实测数据与呈现质量。
- **硬件条件**：ADALM-Pluto SDR（AD9363，325 MHz–3.8 GHz）一块；教师可提供第二块。
- **软件条件**：MATLAB R2024b + Communications / DSP System / Simulink / Instrument Control Toolbox，
  以及 ADALM-Pluto Support Package。

**本项目要回答的问题**：如何从零搭建一条**能在真实空口工作**的 QPSK 收发链路，
并使其在数学上、工程上、呈现上都是一个**完整的通信系统**。

## 4. 端到端信号处理流程（核心）

### 4.1 发射链路

| 步 | 处理 | 实现文件 | 关键参数 |
|---|---|---|---|
| T1 | 内容编码（文字/遥测/图像 → 字节流） | `transmitter/content_encode.m` | 每帧 ≤62 字节 |
| T2 | 组帧：前导(32 符号) + 帧头(16 符号) + 载荷(248 符号) | `transmitter/tx_frame.m` | 共 296 符号 |
| T3 | 加扰：载荷比特 XOR 伪随机扰码 | 同上 | 避免长串 0/1 |
| T4 | QPSK 映射 | `pskmod` | 2 bit/符号 |
| T5 | 上采样 ×4 | `transmitter/tx_baseband.m` | fs = 1 MHz |
| T6 | RRC 脉冲成形 | 同上 | 滚降 β=0.35，跨度 6 符号 |
| T7 | 幅度归一化 ×0.9（充分利用 DAC 量程） | 主脚本 | 避免削波 |
| T8 | DAC → 上变频至 2.4 GHz → 天线 | `sdrtx('Pluto')` | 发射增益低起步 |

### 4.2 信道模型（含损伤注入）

**真实空口**：自由空间衰减 + 加性噪声 + 收发晶振频偏 + 相位漂移 + 采样率失配 +（可能的）多径。

**仿真对照**：在波形域按需注入下列损伤，参数可控，用于**分层验证**：

| 损伤 | 注入方式 | 用途 |
|---|---|---|
| AWGN | `sigma = sqrt(Es·Eg/(2·SNR_sym))` | BER 曲线 |
| 载波频偏 Δf | `·exp(j2πΔf·t)` | 频偏估计量程/精度 |
| **定时偏移 τ** | 对波形做分数延时 | **W7 定时同步验证（对抗实验）** |
| **相位漂移** | `·exp(j·φ(t))`，φ 缓慢变化 | **W7 相位跟踪验证（对抗实验）** |
| 采样率失配 | 重采样因子 K | 长帧定时漂移 |

### 4.3 接收链路（同步链为核心）

| 步 | 处理 | 实现文件 | 状态 |
|---|---|---|---|
| R1 | 下变频 → ADC → 复基带采样（fs = 1 MHz） | `sdrrx('Pluto')` | ✅ |
| R2 | 去直流（DC 偏置去除） | 待加 | ⬜ |
| R3 | **帧检测**：归一化滑动相关 | `sync/frame_detect.m` | ✅ |
| R4 | 匹配滤波（RRC 匹配） | `receiver/rx_frame.m` | ✅ |
| R5 | **定时精调**（TED + 插值） | 经量化评估**决定不单独实现**（真实残余 0.06 T） | ⚠️ 见 `exp_w7a_timing_decision.md` |
| R6 | **频偏估计与补偿**（前导首尾分段相位差） | `sync/freq_sync.m` | ✅ |
| R7 | **公共相位校正**（前导估计常数相位） | `receiver/rx_frame.m` | ✅ |
| R8 | **相位跟踪**（判决导向 PLL，R7 给初值） | 待实现 | ⬜ **W7b** |
| R9 | 判决 → 解扰 → 帧头解析 → 载荷 | `receiver/rx_frame.m` | ✅ |
| R10 | 内容还原 | `receiver/content_decode.m` | ✅ |
| R11 | **连续接收状态机**（滑动缓冲，持续解帧） | `receiver/rx_receiver.m` | ✅ |

### 4.4 完整流程图

```
【发射端】
 内容(文字/遥测/图像)
   → 内容编码(字节流)
   → 组帧[前导32 | 帧头16 | 载荷248] = 296 符号
   → 载荷加扰(XOR)
   → QPSK 映射(2bit/符号)
   → 上采样 ×4 (fs=1MHz)
   → RRC 成形(β=0.35)
   → ×0.9 归一化
   → Pluto DAC → 2.4GHz → 天线
                              │
                    ══════════╪══════════ 空口信道
                    AWGN · 频偏Δf · 定时偏移τ · 相位漂移 · 采样率失配
                              │
【接收端】                    ▼
 天线 → 下变频 → Pluto ADC → 复基带采样
   → [DC 去除]
   → 帧检测(归一化相关 ρ>0.60 → 定位帧起点)        ← 已有
   → 匹配滤波(RRC)
   → 定时精调(TED + 插值)                          ← W7a 新增
   → 频偏估计(前导首尾分段相位差) → 补偿            ← 已有
   → 公共相位校正(前导, 消解4重模糊) → 提供 PLL 初值 ← 已有
   → 相位跟踪(判决导向 PLL)                        ← W7b 新增
   → 判决 → 解扰 → 帧头解析 → 载荷
   → 内容还原 → 输出
   ↺ 连续接收状态机(滑动缓冲)持续循环
```

> **处理顺序**：本系统采用「**粗频偏补偿 → 定时精调 → 精细相位跟踪**」的顺序。
>
> **理由**（而非断言"不可交换"）：三者在原理上相互耦合——
> 频偏表现为旋转、定时表现为时延，并非严格可交换或不可交换。
> 选择该顺序的工程依据是：
> 1. **较大的频偏会同时劣化帧检测与定时误差检测**（实测：帧检测在 ≈3.9 kHz 处失效，见 §6.2），
>    故应先用前导估出的频偏做**粗补偿**，为后续处理创造良好条件；
> 2. **判决导向的相位误差检测依赖判决正确**，而判决正确依赖定时准确，
>    故相位跟踪应放在定时精调之后。
>
> 因此这是**本系统在给定条件下的顺序选择**，不是普适规则。

## 5. 关键技术方案

### 5.1 帧结构

```
| 前导 Preamble | 帧头 Header | 载荷 Payload |
|   32 符号     |   16 符号   |   248 符号   |
|   64 bit      |   32 bit    |   496 bit    |
总计 296 符号 / 592 bit
```

**帧头 32 bit 字段**：类型(2) | 载荷字节数(8) | 帧号(8) | 校验(8) | 保留(6)

- 前导：伪随机 QPSK 序列（固定种子生成，收发两端预置同一份）
  → 同时服务**帧检测**与**频偏估计**
- 载荷不足时补零，由帧头"字节数"字段在接收端截断
- 载荷加扰：避免长串 0/1 导致成形后波形平坦、相关旁瓣恶化

### 5.2 帧检测：归一化滑动相关

$$\rho[n]=\frac{\left|\sum_m r[n+m]\,p^*[m]\right|}{\sqrt{E_r[n]\cdot E_p}},\quad
E_r[n]=\sum_m|r[n+m]|^2,\ E_p=\sum_m|p[m]|^2$$

- ρ ∈ [0,1]，**与接收幅度无关** → 门限可固定，适合连续接收
- 实测标定：真峰 ρ≈0.90，噪声/旁瓣 ρ≈0.35–0.44，噪声底 ρ≈0.17 → **门限取 0.60**
- 对齐关系：相关序列索引即帧起点

> 原理对应统计信号处理中的**匹配滤波 / 二元假设检验**。

### 5.3 频偏估计：前导首尾分段相位差法

1. 去调制：`d = rxPre .* conj(preambleSym)` → 只剩频偏旋转
2. 首尾分段相干平均：`z1 = mean(d(1:Nseg))`，`z2 = mean(d(p-Nseg+1:p))`
3. 相位差：`Δθ = angle(z2·conj(z1))` → `Δf̂ = Δθ / (2π·T_sep)`

- `Nseg = p/4 = 8`，`centerGap = p − Nseg = 24` 符号
- **无模糊估计范围**：`Rs/(2·centerGap) = 250k/48 = ±5208 Hz`（≈ ±2.17 ppm @2.4 GHz）

### 5.4 定时同步 [W7a 新增]

**方案：两级结构 —— 前导相关粗同步 + 局部符号定时精调**

```
Stage 1  粗定时：归一化相关给出帧起点 n̂₀（整数采样）
Stage 2  精定时：在 n̂₀ ± Δ 的小范围内搜索最佳抽样位置
```

**注意区分两个不同的问题**（这是本方案的关键立论）：

| 问题 | 含义 | 由谁解决 |
|---|---|---|
| **帧起点检测** | "信号从哪开始" | 前导相关（已有） |
| **最佳抽样时刻** | "每个符号该在哪抽样" | 定时精调（W7a） |

二者**不等价**。相关峰给出的是帧起点，其精度受噪声、CFO、波形自相关旁瓣影响，
**不能直接假定"残余误差 ≤0.5 采样"**，必须实测（见下方）。

**为什么不做完整 Gardner 环路**：
Gardner（内插滤波 + 误差检测 + 环路滤波 + 环路控制）是为**盲捕获**设计的
——接收端完全不知道符号边界位置，需要从采样流中搜索。
本系统**已有前导相关完成粗定位**，只需在**局部范围**内精调。

因此采用：
```
局部搜索内的最佳抽样位置：TED（早迟门 / Oerder-Meyr）
  + 一次插值（抛物线 / 三次）把抽样点移到真峰
```
不需要环路滤波器与插值控制器，复杂度约为完整 Gardner 的 1/3。

**待实测的量化项**（P6）：当前固定抽样的定时误差容限。
计划通过注入 0 → T/2 的抽样相位偏移扫描，测出 BER 曲线转折点。

> **表述修正**：不再断言"因为前导已定位所以不需要 Gardner"，
> 而是"采用粗同步 + 局部精同步的两级结构，避免全流盲搜索"。

### 5.5 相位跟踪 [W7b 新增]

**这一模块的必要性有实测支撑**（见 §12.0 问题 B，`notes/exp_baseline_metrics.md` §E2/E3）：

> 现有接收机的误码**不是噪声造成的，而是频偏估计残余造成的**。
> 实测：帧内 BER 从帧首 **0.0000** 单调恶化到帧尾 **0.3857**；
> 若已知真频偏、不做帧内补偿，则全帧 BER = **0.0000**。
> 折合：频偏估计标准差 84.2 Hz @12 dB → 帧内相位漂移 **35.9°**（判决边界 45°）。
> 后果：现有接收机需 **≈20 dB** 才能无误码，而理想同步 **8 dB** 即可。

**方案：判决导向 PLL（DD-PLL）**

| 功能 | 由谁承担 | 说明 |
|---|---|---|
| **相位模糊消除**（分辨 0/90/180/270°） | **公共相位校正**（已有，W3 修复） | 这是**检测/分辨**问题 |
| **帧内相位跟踪**（吸收残余斜坡） | **DD-PLL**（W7b） | 这是**跟踪**问题 |

⚠️ **注意**：这两个是**不同的功能**，不可混为一谈。
实测（`exp_baseline_metrics.md` §E8）：注入 0/90/180/270° 固定相位，
现有系统的 BER 量级一致且无灾难性错误 → **相位模糊问题已经解决**。
W7b 要解决的是**帧内相位漂移的跟踪**。

**关键风险与对策**：DD-PLL 若初值错误，会锁死在错误的 2π/M 整数倍相位（**跳周**）。
**对策**：用**前导公共相位校正**的结果 `ph0` 作为 PLL 初始相位。
因 `ph0` 已由已知前导序列解出、且消解了相位模糊，
PLL 只需跟踪前导之后的**小**残余漂移，跳周风险显著降低。

**量化目标（对应 P3/P7）**：使 BER 曲线从"20 dB 才无误码"逼近"8 dB 无误码"，
即可跟踪的帧内相位漂移 ≥ 56.8°。

> 这一步把已有的"开环常数校正"升级为"闭环跟踪"，属于自然演进。

## 9. 呈现方案

### 9.1 呈现载体决策：主函数 vs GUI vs Simulink

**四个档位对比**：

| 档 | 形式 | 投入 | 可回归测试 | 现场观感 | 决策 |
|---|---|---|---|---|---|
| **基础** | 主函数脚本 + 保存图片 | 已完成 | ✅ 可以 | 一般 | 保留（报告插图来源） |
| **推荐** | **主函数 + 实时图形对象**（轻量 GUI） | 低 | ✅ 可以 | 好 | ✅ **采用** |
| 增强 | Simulink 实时监视器 | 中 | ❌ 不可（仅 GUI 运行） | 很好 | ✅ 采用（互补） |
| 可选 | App Designer 完整 GUI | 高 | ❌ 困难 | 很好 | ⬜ 视课程要求 |

**决策与理由**：

1. **以主函数为算法与实验引擎**（保持现状）。
   这是"结果可复现、可自动回归"的根基，不能放弃。

2. **不做重量级 App Designer GUI，改用"主函数 + 实时图形对象"**。
   在接收循环中直接使用 MATLAB 的实时图形对象
   （`spectrumAnalyzer` / `scatterplot` / `timescope` / `dsp.ArrayPlot`）刷新显示，
   仅需数十行代码即可达到接近 GUI 的现场观感，投入产出比显著优于 App Designer。

   **理由**：App Designer 的价值主要在"界面美观"，不增加技术深度；
   而它与算法耦合后会破坏"可回归测试"这一核心优势（见 §3.1 设计原则）。

3. **Simulink 仅承担"系统层"**：
   实时可视化与架构视图，**不重写算法**（用 MATLAB Function 块调用 `.m` 函数）。
   明确**不做**全盘 Simulink 重写，理由：
   - 算法零新增（搬过去跑的是同一套逻辑）
   - 双实现分叉风险（改一处需改两处，不一致时无法自证正确）
   - 硬件 Simulink 模型仅能 GUI 运行，**无法进入自动化回归测试**

4. **若课程明确要求 GUI 交付**：可用 App Designer 做"薄壳"——
   仅负责参数输入与结果展示，算法仍调用 `.m` 函数，不产生分叉。

> - 另一个负结果：**批量判决导向精估彻底失败**（帧尾判决出错导致估计崩溃），
>   这也从反面说明 PLL 的"局部判决逐步跟踪"才是正确机制。

## 附录 C：术语表

| 术语 | 含义 |
|---|---|
| **收发系统** | 同时包含发射与接收的完整通信系统 |
| **旁路捕获 (粗捕获)** | 初步确定信号/帧的大致位置 |
| **TED** | Timing Error Detector，定时误差检测器 |
| **PLL** | Phase-Locked Loop，锁相环 |
| **判决导向** | 用判决结果作为相位误差检测的参考（Decision-Directed） |
| **跳周** | 相位锁定到错误的 2π/M 整数倍相位上 |
| **4 重相位模糊** | QPSK 因星座对称性，相位可能相差 90° 的整数倍而无法区分 |
| **RRC** | Root Raised Cosine，根升余弦（脉冲成形/匹配滤波） |
| **ISI** | Inter-Symbol Interference，符号间干扰 |
| **Eb/N0** | 每比特能量与噪声功率谱密度之比 |
| **SFDR** | Spurious-Free Dynamic Range，无杂散动态范围 |
| **ppm** | parts per million，百万分之一（晶振频率误差单位） |
